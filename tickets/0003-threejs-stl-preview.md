# Ticket #0003: Interactive Three.js 3D STL Viewer

**Status**: Open
**Priority**: Medium-High
**Estimated Effort**: 8-12 hours
**Created**: 2026-01-06
**Related Docs**: `docs/04-OPENSCAD-GENERATION.md`, `docs/01-FRONTEND-UI.md`

## Summary

Users currently cannot interactively inspect the generated 3D model before downloading the STL file. The current implementation only displays static PNG preview images generated by OpenSCAD, which provides limited perspective and no ability to examine the model from different angles.

This ticket adds an interactive 3D viewer using Three.js that allows users to rotate, zoom, and pan the STL model directly in the browser before downloading, providing better quality assurance and user confidence.

---

## Problem Statement

### Current State
- `STLPreview.tsx` component only fetches and displays static PNG images from the `/api/preview` endpoint
- Preview images are generated server-side by OpenSCAD with fixed camera angles
- Users cannot inspect the underside, sides, or specific details of the bin
- No way to verify that the cutout shape, magnet holes, or other features are correctly positioned
- Limited visual feedback before committing to a potentially lengthy 3D print

### User Impact
- Users must download the STL and open it in external software (slicer/CAD) to inspect the model
- Increases friction in the workflow and reduces confidence in the generated output
- May lead to wasted prints from models that don't meet expectations
- Poor user experience compared to modern 3D model viewers (Thingiverse, Printables, etc.)

### 2. Component Architecture

Replace the current static image preview with an interactive 3D viewer:

**File**: `/components/generation/STLViewer.tsx` (new component)

```typescript
interface STLViewerProps {
  stlUrl: string;
  onError?: (error: Error) => void;
  showGrid?: boolean;
  showAxes?: boolean;
  autoRotate?: boolean;
}
```

**Key Features**:
- Uses `Canvas` from `@react-three/fiber` for rendering
- Uses `STLLoader` from `three/examples/jsm/loaders/STLLoader` to parse STL files
- Uses `OrbitControls` from `@react-three/drei` for camera interaction
- Uses `Environment` and `ContactShadows` from `@react-three/drei` for realistic lighting

### 3. Implementation Details

#### STL Loading
```typescript
// Load STL geometry asynchronously
const loader = new STLLoader();
loader.load(
  stlUrl,
  (geometry) => {
    geometry.center(); // Center the geometry at origin
    geometry.computeVertexNormals(); // Ensure smooth shading
    setGeometry(geometry);
  },
  (progress) => {
    setLoadProgress((progress.loaded / progress.total) * 100);
  },
  (error) => {
    setError(error);
    onError?.(error);
  }
);
```

#### Scene Setup
```typescript
<Canvas camera={{ position: [100, 100, 100], fov: 50 }}>
  {/* Lighting */}
  <ambientLight intensity={0.4} />
  <directionalLight position={[10, 10, 5]} intensity={0.8} castShadow />
  <pointLight position={[-10, -10, -5]} intensity={0.3} />

  {/* STL Mesh */}
  <mesh geometry={geometry} castShadow receiveShadow>
    <meshStandardMaterial color="#e0e0e0" roughness={0.3} metalness={0.1} />
  </mesh>

  {/* Controls */}
  <OrbitControls
    enableDamping
    dampingFactor={0.05}
    minDistance={50}
    maxDistance={500}
  />

  {/* Helpers */}
  {showGrid && <gridHelper args={[200, 20]} />}
  {showAxes && <axesHelper args={[50]} />}

  {/* Shadows */}
  <ContactShadows
    position={[0, -binHeight/2, 0]}
    opacity={0.4}
    scale={150}
    blur={2}
  />
</Canvas>
```

#### Performance Optimizations
- Use `useMemo` to cache geometry after loading
- Enable frustum culling for off-screen objects
- Limit shadow map resolution (1024x1024)
- Throttle resize events
- Dispose of geometries and materials on unmount

### 4. Component Integration

Update `STLPreview.tsx` to use the new viewer:

```typescript
export function STLPreview({ previewUrl, svg, config, quality }: STLPreviewProps) {
  const [stlUrl, setStlUrl] = useState<string | null>(null);
  const [mode, setMode] = useState<'3d' | 'static'>('3d');

  // When generation completes, fetch the STL URL
  useEffect(() => {
    if (generationId) {
      const url = `/api/download/${generationId}`;
      setStlUrl(url);
    }
  }, [generationId]);

  return (
    <Card>
      <CardHeader>
        <CardTitle className="flex items-center justify-between">
          <span>3D Preview</span>
          <div className="flex gap-2">
            <Button
              variant={mode === '3d' ? 'default' : 'outline'}
              size="sm"
              onClick={() => setMode('3d')}
            >
              <Cube className="w-4 h-4" />
              3D View
            </Button>
            <Button
              variant={mode === 'static' ? 'default' : 'outline'}
              size="sm"
              onClick={() => setMode('static')}
            >
              <Image className="w-4 h-4" />
              Static
            </Button>
          </div>
        </CardTitle>
      </CardHeader>
      <CardContent>
        {mode === '3d' && stlUrl ? (
          <STLViewer
            stlUrl={stlUrl}
            showGrid={true}
            showAxes={false}
            autoRotate={false}
          />
        ) : (
          <StaticImagePreview url={previewUrl} />
        )}
      </CardContent>
    </Card>
  );
}
```

### 5. Fallback Strategy

If STL is not yet available (during generation):
1. Show the static PNG preview from OpenSCAD
2. Display a badge indicating "3D preview available after generation completes"
3. Automatically switch to 3D view when STL becomes available

If 3D viewer fails to load:
1. Catch errors and display fallback message
2. Show static preview as alternative
3. Log error details for debugging

## Edge Cases & Considerations

### Performance
- **Large STL files**: Implement progress indicator, consider file size warnings
- **Low-end devices**: Detect hardware capabilities, auto-disable shadows on weak GPUs
- **Memory constraints**: Dispose of old geometries when switching models

### Browser Compatibility
- **WebGL not supported**: Show clear error message, fallback to static preview
- **Safari quirks**: Test specifically for iOS Safari WebGL issues
- **Mobile browsers**: Reduce quality settings for mobile devices

### Network Issues
- **Slow connections**: Show download progress, allow cancellation
- **Failed downloads**: Retry logic with exponential backoff
- **CORS issues**: Ensure STL files are served with correct headers

### Accessibility
- **Screen readers**: Canvas is not accessible; provide detailed text description
- **Keyboard-only users**: Ensure all controls are keyboard accessible
- **Color blindness**: Don't rely solely on color for state indication
